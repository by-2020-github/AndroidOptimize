# 名单格式说明

应用名单是这套工具的核心资产。程序与名单完全分离：**改名单不需要重新编译程序**，
只要替换 `data/packages.json` 或 `data/protected.json` 即可。

---

## 一、加载顺序

程序按下面的顺序找一个配置文件，找到就用，找不到就往下退：

1. `%LOCALAPPDATA%\AndroidOptimize\data\<文件名>`　← 用户数据目录（以后在线更新写这里）
2. `<程序目录>\data\<文件名>`　　　　　　　　　　← 发布包里带的
3. 程序内置的副本　　　　　　　　　　　　　　　　← 保底，保证离线也能跑

所以测试新名单时，把它丢到 `%LOCALAPPDATA%\AndroidOptimize\data\` 就能覆盖发布包里的版本。

---

## 二、packages.json

顶层结构：

```json
{
  "schemaVersion": 1,
  "listVersion": "2026.09.19.1",
  "updatedAt": "2026-09-19",
  "channel": "stable",
  "packages": [ ... ],
  "settings": [ ... ]
}
```

除了 `packages` 和 `settings`，还有第三个数组 `policies`（全局策略），见下文第四节。

还有一个顶层的 `unknownExclude` 数组，见第五节。

### 应用规则字段

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | ✅ | 包名，例如 `com.xiaomi.market` |
| `name` | | 中文名称，界面和报告里显示这个 |
| `brands` | | 适用品牌，`["*"]` 表示全品牌。可用值：`xiaomi`/`redmi`/`poco`、`vivo`/`iqoo`、`oppo`/`oneplus`/`realme`、`huawei`、`honor`、`samsung` |
| `category` | | 分类，例如 `广告与跟踪`、`应用分发`、`快应用` |
| `tier` | ✅ | `normal` / `geek` / `danger`，决定它出现在哪个档位 |
| `risk` | ✅ | `low` / `medium` / `high`。`high` 永远不会被默认勾选 |
| `action` | ✅ | `disable` 停用 / `uninstall` 卸载 / `restrict` 后台限制 / `keep` 确认保留 |
| `confidence` | ✅ | 0~1，人工确认程度。低于当前档位门槛的条目不会被列出 |
| `reason` | | 为什么建议处理，一句话讲清楚 |
| `impact` | | 处理后会失去什么 |
| `appOps` | | 仅 `restrict` 使用，形如 `[{"op":"WAKE_LOCK","mode":"ignore"}]` |
| `standbyBucket` | | 仅 `restrict` 使用，通常是 `restricted`，失败会自动退回 `rare` |
| `ignoreSafetyMode` | | 为 `true` 时该项不受「安全模式」影响，始终按 `action` 执行。目前只用于应用商店 |

### 档位的置信度门槛

| 档位 | 最低 confidence | 效果 |
|---|---|---|
| 一般优化 | 0.75 | 只出现被反复验证过的条目 |
| 极客模式 | 0.50 | 含中等把握的条目 |
| 深度模式 | 0.00 | 全部列出，但低置信度项默认不勾选 |

这就是处理"这个包能不能删我不确定"的标准做法：**不确定就压低 confidence**，
而不是凭猜写进一般档位。程序会把它降级到深度模式，并且默认不勾选。

### 设置项字段

```json
{
  "id": "global.animation_scale",
  "name": "系统动画速度",
  "brands": ["*"],
  "category": "流畅度",
  "tier": "normal",
  "risk": "low",
  "action": "settings",
  "confidence": 0.95,
  "namespace": "global",
  "keys": ["window_animation_scale", "transition_animation_scale", "animator_duration_scale"],
  "choices": [
    { "label": "0.75x（推荐）", "value": "0.75" },
    { "label": "1x（系统默认）", "value": "1" }
  ],
  "defaultChoice": "0.75",
  "reason": "...",
  "impact": "..."
}
```

固定值用 `value`；需要用户挑选时用 `choices` + `defaultChoice`。

## 三、protected.json

```json
{
  "schemaVersion": 1,
  "listVersion": "2026.09.19.1",
  "patterns": [
    {
      "match": "com.android.providers.*",
      "level": "absolute",
      "category": "数据提供者",
      "reason": "联系人、短信、媒体等数据提供者，停用会导致数据丢失"
    }
  ]
}
```

`match` 支持 `*` 通配符（`*bank*`、`com.android.*`）。
匹配优先级：**精确匹配 > 更长的通配符**。

`level` 有两种：

| level | 含义 |
|---|---|
| `absolute` | 任何档位、任何来源（含 AI 建议）都不得操作 |
| `guarded` | 默认不勾选、AI 不得建议；用户打开「允许操作受保护应用」后可手动选择 |

判断某个包该进保护名单的经验法则：**删掉之后用户会"不会用手机"或"蒙受损失"的，一律 absolute。**
输入法、电话短信联系人、桌面、系统界面、安装器、无障碍、反诈、支付、银行、政务、医保，都属于这一类。

## 四、policies：全局策略

名单规则是「一个包一条」，而策略是「按条件作用到一批应用」。目前只有一条：传感器权限。

```json
{
  "id": "sensor_lock",
  "name": "关闭传感器权限（防摇一摇广告）",
  "category": "传感器权限",
  "tier": "normal",
  "risk": "low",
  "action": "restrict",
  "confidence": 0.8,
  "defaultEnabled": true,
  "scope": "thirdParty",
  "exclude": ["com.tencent.mm", "*map*", "*health*"],
  "appOps": [
    { "op": "BODY_SENSORS", "mode": "ignore" },
    { "op": "HIGH_SAMPLING_RATE_SENSORS", "mode": "ignore" },
    { "op": "ACTIVITY_RECOGNITION", "mode": "ignore" }
  ],
  "standbyBucket": null,
  "reason": "...",
  "impact": "..."
}
```

| 字段 | 说明 |
|---|---|
| `scope` | `thirdParty` 只作用于第三方应用；`all` 连系统应用一起 |
| `exclude` | 排除名单，支持 `*` 通配符。微信、地图、运动健康类都在这里 |
| `appOps` | 要下发的权限限制。**留空则只做 `standbyBucket`** |
| `standbyBucket` | 留空表示**不动后台策略**，只下发 `appOps` |

几点设计约束，改动时请遵守：

1. **保护名单永远优先于策略。** 即使 `exclude` 里写漏了微信，策略也不会碰到它。
2. **同一个应用只出一行。** 如果这个应用在 `packages` 里已经有 `restrict` 规则，
   策略的 `appOps` 会**合并进那一行**，而不是再出一条重复的。
3. **会被停用或卸载的应用不需要策略。** 都已经停掉了，再关传感器没有意义。
4. `scope` 建议保持 `thirdParty`。系统应用里有相机、指南针这类真的需要传感器的，
   放开会给用户带来莫名其妙的故障。

### 关于传感器限制的真实效果

标准 Android **没有**给加速度传感器设置权限门控，所以 ADB 能下发的只有上面这几项
（心率传感器、高采样率传感器、运动识别）。能挡到什么程度取决于系统版本与厂商实现。

程序对每一项都会**回读校验**，并在「执行结果」页如实显示通过还是失败，不会假装成功。
如果将来发现更有效的 op，直接加进 `appOps` 即可，不需要改代码。

## 五、unknownExclude：不算「垃圾」的正常应用

程序会把「名单里查不到、也不在保护名单里」的第三方应用归为**未知应用**，
让用户可以用「一键选中从未打开过的应用」批量处理——这是给「老人手机里被莫名装了一堆应用」准备的。

`unknownExclude` 就是这份排除名单，避免把明显正常的应用也列进去：

```json
"unknownExclude": [
  "com.tencent.mm",
  "*map*",
  "*gaode*",
  "*health*",
  "*hospital*",
  "cn.wps.moffice_eng"
]
```

支持 `*` 通配符。目前覆盖：微信 / QQ、地图导航、运动健康、医院挂号、出行票务、办公软件。

**判断依据**：这类应用「装了但没打开过」很常见（出远门才开一次地图），
但它们是正常应用，不该被当成垃圾清掉。

注意区分三份名单的职责：

| 名单 | 作用 |
|---|---|
| `protected.json` | 绝对不能动的（反诈、支付、输入法…），优先级最高 |
| `packages.json` 的规则 | 明确知道是什么、该怎么处理 |
| `packages.json` 的 `unknownExclude` | **不知道具体是什么**，但明显属于正常应用，不列为「未知」 |

### 判断「从未打开过」靠什么

靠系统自己记录的 `notLaunched` 标记（来自 `dumpsys package <包名>` 的 `User 0:` 行），
不是猜测。装完后从未启动过的应用该值为 `true`。

如果某台设备的输出里没有这个字段，程序会把它标为「无法判断」，
并在用户点「一键选中从未打开过的应用」时明确说明，不会瞎勾。

## 六、lazyMode：懒人模式的白名单

懒人模式不做任何猜测：**「必须保留清单」之外的项目全部勾选处理**。
这是给「给长辈收拾手机」准备的——老人手机里往往只有微信、抖音、快手、地图、银行，
其余都可以清掉，一个个勾太慢。

```json
"lazyMode": {
  "name": "懒人模式",
  "description": "...",
  "keep": [
    "com.tencent.mm",
    "com.ss.android.ugc.aweme",
    "com.smile.gifmaker",
    "*map*",
    "com.autonavi.*",
    "cn.wps.moffice_eng"
  ]
}
```

`keep` 支持 `*` 通配符。**保护名单里的应用会自动保留，不需要在这里重复写**——
判断顺序是：

```text
protected.json 命中  →  保留（优先级最高）
  ↓ 没命中
lazyMode.keep 命中   →  保留
  ↓ 没命中
                     →  勾选处理（停用）
```

### 维护建议

1. **宁可多留，不可错删。** 这份清单直接决定「删什么」，写漏一个就是真的被清掉。
   拿不准的一律加进来。
2. **按类别写通配符**比逐个列包名更省事，例如 `*map*`、`*hospital*`、`*health*`。
   但要注意通配符可能误伤（`*map*` 会匹配到 `minimap`、`mapbar` 之类），
   加完最好扫一眼实际命中了哪些。
3. **老人家里、社区、医院自建的 App 最容易被漏掉**，这类包名通常没有规律，
   建议平时看到就补进去。
4. 改完之后跑一次自检（`--selftest`），里面有专门的懒人模式检查项。

## 七、维护名单的建议流程

1. **AI 建议 → 人工复核 → 进名单**。
   桌面版识别出的未知应用只作为建议，不要直接相信。确认过用途之后，
   再按上面的格式写一条记录进 `packages.json`，这才是名单长大的方式。

2. **不确定就压低 confidence**，让它落到深度模式，而不是混进一般档位。

3. **改完跑一次自检**：

   ```powershell
   AndroidOptimize.exe --selftest out.txt
   ```

   自检会校验名单能否解析、保护规则是否命中、各个档位的计划是否符合预期。

4. **发布前一定要升 `listVersion`**（推荐 `年.月.日.序号`），
   这样从用户日志里一眼就能看出用的是哪一版名单。

5. 涉及"是否该删"有争议的包，宁可先写成 `keep` 并写清 reason，
   也不要凭印象写进 `disable`。名单里的每一条都会直接作用在别人的手机上。
